# 5.1 窗口响应修正

按最终确认列表实施。分支：`fix/5.1-window-responsiveness`。本文件取代先前包含 I/O Worker 与逐请求 ACL 检查的草案。

## 保留的功能

每台电脑首次授权安装两项 SYSTEM 管理员后台服务。之后服务自动启动，正常打开窗口无需重复 UAC。桌面程序访问现有服务，Windows 下不会降级启动普通权限后台。更改窗口的登录启动偏好不撤销服务自动启动。

一台连接五台、五台连接一台可以同时操作，不抢占控制权。每台设备独立断开。第六台仍需用户选择保留或替换指定连接。统一程序的两项功能可独立开启、同时开启并记住状态。

配对、凭据认证、设备记忆、自动重连、命令执行、文件传输及连接准入规则继续沿用。

## 修改表

| 行为 | 实施方式 |
| --- | --- |
| 请求前额外检查文件访问权限 | 删除 Agent 启动和客户端请求中的该项检查；直接读取现有凭据，后台仍验证令牌 |
| 等待外部命令卡住窗口 | 服务查询、首次安装、快捷方式创建使用异步外部命令；导出诊断在独立短进程执行 |
| 正常查询反复检查后台启动 | 启动时初始化；日常直接请求；仅状态查询遇到传输故障才按需进入现有恢复流程，修改命令不自动重发 |
| 相同状态重复读取 | 每个角色合并在途状态查询；可见窗口由一个刷新调度器每轮完成后等待 3 秒 |
| 第六台单独轮询 | 复用远端状态及同一快照；隐藏时仅保留允许入站所需的 3 秒检查 |
| 隐藏时无用工作 | 停止近端展示查询、DOM 刷新和日志读取；重新显示时立即刷新 |
| 全部设备行重建 | 按设备 ID 保留节点，仅更新变化字段，不打断焦点及行内操作 |
| 操作后刷新丢失或过时 | 刷新期间收到新刷新要求时再执行一轮；同一行冲突操作等待当前操作完成 |
| 日志一直读取 | 默认收起，展开且可见时读取，每轮完成后等待 5 秒 |
| 一个错误覆盖整个窗口 | 两端状态分别显示失败原因，日志读取错误单独显示 |
| 配置与配对码 | 启动时加载设置，保存后读取确认；配对码本地到期清除，不按秒查询 |

不增加 Worker、权限变化监听、旧后台识别、更新系统或新的业务恢复框架。服务首次安装仍设置原有目录权限，以便桌面账户与 SYSTEM 共用同一身份；删除的是运行时反复检查，并非破坏安装后的访问设置。

## 交付与实际操作

不运行测试套件。使用隔离身份，通过现有公共中继完成实际配对、连接及操作遍历；操作记录另见本分支 `5.1-RESPONSIVENESS-OPERATIONS.md`。

开发模式使用原有 `Start-Dev.cmd` / `Start-Dev.sh`。运行包使用复制式打包及低压缩，包含固定版本运行时与生产依赖；解压一个文件夹即可运行 `Start.cmd`，`Restart.cmd` 重新打开界面。缓存、私有身份与运行记录不进入运行包。
