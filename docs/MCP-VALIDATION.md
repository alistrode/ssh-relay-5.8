# MCP 验证范围

本记录区分源码实现、MCP 协议发现、真实远端执行和外部业务依赖。测试过程的连接块、私钥、状态、日志和临时样本不提交仓库。

## 协议与工具链

通过官方 MCP SDK stdio 客户端实际发现 37 个工具、5 个 prompts 和 1 个手册资源；读取 prompt 和资源成功。Linux 公网集成共 54 次工具调用覆盖 37 个工具名称，验证实际 stdout、stderr、失败退出码、文件内容和副作用。全部处理器存在并可调用，不以 tools/list 作为业务执行成功的替代。

实测成功：单文件中文内容往返、SFTP 同步 dryRun/exclude/checksum/delete、Linux 持久 cwd/env、会话失败退出码、系统健康及进程查询、日志读取、告警配置读取与检查、文件备份/列举/校验还原、带备份部署、目标/命令别名、Profiles、Hooks 状态、分组批量执行、历史、固定指纹核验，以及正向和反向回环转发的实际数据往返。

额外 11 次调用验证命令超时后可建立新执行、同步超时、密钥撤销阻止执行及恢复、分片 SOCKS5 握手和实际数据往返，以及拒绝非回环绑定/目标。超时子进程停止运行；超时不保证副作用回滚。

## Windows 实机

最终完整回归 26 次调用（含清理）通过。已通过获授权的真实 Windows 连接验证：PowerShell 命令、真实 stderr/错误退出码、原生命令退出码、错误 cwd 拒绝继续执行、中文 SFTP 往返、持久 PowerShell cwd/env、会话错误、健康/磁盘监控、服务与进程查询、日志、现有管理员令牌执行、临时文件备份还原、Windows Profile 别名及带备份部署。临时目标目录清理，不修改系统服务、注册表或全局 ACL。

实测修复两类 Windows 问题：CMD 对 Node -e 的引号处理可能产生空输出却返回 0，改由编码 PowerShell 执行；较大远端任务可能超过 CMD 限长，改为私密临时文件执行并清理。网络握手曾出现超时，建立连接可对网络错误及只读身份探测重试一次；实际用户命令不重放。

用户当前运行的旧 far 不包含本次新增的 SFTP SETSTAT 修复、进程树中断和回环转发能力。不能把云端新 far 的测试当成该旧 Windows far 已支持新能力；需要用户停止旧实例后从本分支启动新版。Windows 端没有执行数据库导入、计划任务注册、服务重启或杀死用户业务进程。

## 公网连续性

验收要求：云端独立 near/far 进程，经过 wss://broker.emqx.io:8084/mqtt，SSH 固定主机指纹，持续输出和空闲长连接并行，加独立 SSH 和 SFTP 往返；连续至少 600 秒。云端自测明确标记，不冒充用户电脑。

首轮在约 153 秒关闭，未算通过；当时短命令/传输成功且 broker 未报告离线，不能据此定性根因。第二轮显式隔离 OpenSSH stdin 并启用保活，连续 660.0 秒通过：33 次 SSH 探测、11 次 64 KiB 文件往返，持续输出和空闲长连接均以退出码 0 完成，期间 near/far 均无 broker 离线记录。该历史通过只对应当时源码，不能证明已解决并发丢包；本次稳定性修复与新验收另见下文。

## 尚未完成业务验收的依赖

云端没有 MySQL/PostgreSQL/MongoDB 客户端或数据库服务，也没有 crontab。已核验真实依赖缺失和无效输入返回错误，不冒充数据库 dump/import/query 或定时任务注册成功。实现使用远端已有客户端、只读 SQL 事务、JSON MongoDB find，以及平台调度器；要证明实际业务成功仍需相应服务和获授权的测试数据。

Hooks 的状态/开关已验证，预设 Frappe/Docker/Node.js 的实际业务动作未在真实应用上执行。服务重启、真实进程 kill、数据库还原、计划任务安装均未用于用户的业务环境验收。

最终补充 6 次调用验证带合成凭据的数据库依赖失败仍被脱敏、无效别名拒绝、Profile 立即切换及分组列表。所有应用模块通过 Node 语法检查，近远端构建通过。主分支和纯源码分支保持原提交；本次不安装系统依赖、不改环境配置、不自动注册 MCP。

## 接收端交付修复（2026-10-16）

旧链路把 MQTT QoS 1 的 PUBACK 当成对端交付成功。公网复现中，发送端记录 PUBLISH 和对应 PUBACK，但接收端未出现相同签名数据包摘要，没有认证/解析拒绝记录，broker 也没有报告离线。后续序号到达时旧版直接因缺号关闭，或 SSH 握手一直等待。历史约 153 秒事件缺少同等完整证据，不能追溯断言其根因完全相同。

同一公共 broker、严格固定 SSH 指纹、4 个并发 SDK 客户端、45 秒 readyTimeout、无重试的对照：旧版 12 次中失败 5 次。新实现使用接收端累计 ACK、重传、乱序缓存与去重、有限发送窗口、全局节流、reset 确认重传及每帧实例标识。单独收到 broker PUBACK 不释放待交付帧；短暂缺包恢复不重新执行用户命令。容量仍为 8 条 SSH 流，超出明确拒绝。持续丢包 30 秒后明确失败；不保证免费 broker 的服务可用性。

自动故障注入通过 npm run test:relay 执行：内存 MQTT 故意对丢失报文返回 PUBACK，传输使用真实回环 TCP。覆盖容量拒绝且保留既有 8 条连接、256 KiB 精确往返、opened/data 丢失、ACK 丢失、乱序重复、reset/reset_ack 连续丢失与持续数据丢失。测试辅助代码不属于 src/ 应用源码；不能拿内存测试替代公网验收。

公网验收使用云端独立 near/far，经正常 HTTPS 代理访问公共 MQTT WSS，不走直连近远端捷径；真实核验 SSH 指纹、whoami 和 hostname。长连接客户端显式关闭 ServerAliveInterval，避免靠新增客户端保活掩盖空闲断线。长连接与短 SSH、64 KiB SFTP 往返、4 并发 SDK 探测混合运行；另在同版本实例上与 MCP 的 54 次工具回归混合验证。那一轮长测因环境切换中断，未计为完整通过，随后以独立后台进程重跑完整长测。最新应用快照与 src/ 下近远端模块逐字节一致。结果见 MCP-STABILITY-RESULTS.json。

另以真实公网连接中断并重启自己的近端：旧 SSH 非零退出，远端旧命令停止，新连接恢复成功，计数文件只写入一次。实例标识随每个签名帧携带，因此一次状态通知丢失不再让旧任务一直滞留。该项为云端自测，不是用户 Windows 实机升级验证。

本次未擅自更新用户运行中的旧 Windows far。两端均升级且报告 relayProtocol=2 才拥有本次可靠交付能力；旧协议 1 的兼容连接不算已修复。连接 Skill、MCP prompts、操作手册和排查说明同步更新；诊断元数据轮转保存于私密运行目录，不提交原始日志或凭据。

最新独立后台公网验收完成于本轮：连续 660.101 秒，33 次 SSH 探测、11 次 64 KiB SFTP 往返全部通过，持续输出及空闲长连接均退出 0；零 broker 离线、零交付超时。日志记录 91 次帧重传和 35 次乱序缓存，实际完成内容一致；并发原始 SDK 探测 32/32 成功，45 秒握手超时且不重试。该结果来自最新近远端源码，不使用环境中断的那一组冒充通过。
