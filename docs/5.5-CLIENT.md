# SSH Relay Pro 5.5

## 当前行为

- 客户端、托盘与连接服务一起运行。后台不提供独立启动模式；MCP/CLI 会复用或打开完整客户端。
- 窗口关闭收起到托盘。客户端进程异常退出后由父守护进程自动重开；渲染进程异常退出重载界面；守护退出时由客户端心跳重新启动守护。
- 只有托盘的“退出（关闭全部连接和进程）”触发主动退出。先停用恢复、清理本配置目录所属的 Agent、Guardian、Worker、任务和会话进程，再退出客户端和守护。清理失败会保留界面并显示错误，不冒称退出完成。
- 升级自动移除同一配置目录的旧独立系统服务，保留设备身份、配对记录和功能开关。Windows 系统服务迁移需系统授权；不停止其他目录的服务。新版本使用客户端自身的账户与权限，原 SYSTEM 服务的权限不会冒称为普通客户端权限。
- 启动设置只有“随系统自动启动客户端”，没有应用登录流程、登录文案或独立后台选项。
- 主动连接与被连接各最多 20 台；设备槽位、远端准入、组操作和界面容量一致。
- 本机和两端设备显示系统名称、版本、构建号与架构。远端信息来自配对与已认证状态，近端信息通过原设备密钥签名上报。旧设备尚未上报时明确显示待更新，不猜测系统版本。
- 两组列表均有全选、复选框、拖动框选（Ctrl 追加）、取消选择、批量连接/允许连接、断开、取消配对/授权，以及一键全部操作。批量结果显示逐台失败原因，不把部分失败显示成全部成功。
- 所有操作按钮提供按压、处理中、完成或失败反馈。复制配对码显示明确成功提示；未生成配对码时复制按钮不可用。
- 保留 5.5 的 AI 自动重连和任务继续规则。原工具参数不变，仅同步容量说明。

## GitHub 实际运行

工作流：`.github/workflows/run-5.5.yml`。在 Windows Server 2022 和 Ubuntu 24.04 runner 安装原生 Electron 后，启动实际客户端及两项连接服务，读取实际系统信息，保存截图，并调用托盘退出项的内部处理器关闭应用。运行记录与完整源码 ZIP 保存到本分支 run-records/<运行编号>/<平台>/ 目录，不包含配对码、私钥或运行状态目录。

按用户要求不创建或运行测试套件。GitHub 运行不等同于 Windows 10/11 用户实机、20 台物理电脑并发连接、物理鼠标点击托盘或整机重启已验收。
