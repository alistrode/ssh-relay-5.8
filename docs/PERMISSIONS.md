# 本机 Codex 与远程操作的权限对照

目标是同一目标电脑、同一账户、同一实际操作的权限一致。SSH 用户名 relay 是连接认证别名，不能用它推断 Windows 账户或权限。实际身份看 permission_context、whoami 及实际操作结果。

## 已实现的启动检查

Windows 启动远端前检查继承令牌的受限 SID 数、完整性级别、UAC 类型、账户 SID。检测到受限 SID 或低于普通桌面进程的完整性级别时，以 REMOTE_RESTRICTED_TOKEN 停止启动，而不是继续打印一个看似正常的连接块。普通管理员账户的 UAC 未提升状态本身不会被视为受限 SID 错误。

这一检查不能自行提升权限，也不能证明任意文件可访问。已存在的 ACL、用户配置、映射盘、网络登录权限及工具策略仍需按实际失败操作诊断。远端命令与 SFTP 均继承服务进程的权限。

## 正常启动

先停止旧的远端实例，避免同一连接配置下多个进程混用，再在目标电脑上由用户在正常桌面会话双击 START-REMOTE.cmd，或在获授权的正常终端运行 npm start。不要从已知受限的进程启动后，期待 SSH 自动消除限制。如本机 Codex 使用的是获授权的提升终端，远端也应由用户通过同等级终端启动。项目不会自动请求管理员、修改 UAC、全局 ACL 或系统服务配置。

## 验收对照

1. 在目标电脑本机 Codex 的实际命令执行环境、仓库根目录运行 npm run --silent permissions，将纯 JSON 保存到仓库之外。
2. 在同一目标电脑正常启动远端，导入连接块；连接报告中的 permission_context 给出远端服务自报上下文；还必须通过实际 SSH 命令链运行目标仓库的 node src/permissions.cjs，取得执行端报告，不能只依赖广播状态。它尚未自动与本机报告比较，不能把该字段出现当作权限已相等。
3. 核对账户 SID、受限 SID、完整性级别、UAC 类型，以及同一项目目录。Windows 两端还应运行 whoami /all，对照启用或仅拒绝的组及权限；必要时用 icacls 只读查看失败目录的 ACL。报告字段一致仍不等于每个目录的有效权限一致。Linux 对照 UID、有效 UID、组。
4. 在用户指定的同一失败路径对照实际创建、读取、修改、重命名、删除和所需开发命令。仅使用可清理的测试文件，不改已有文件或 ACL。
5. 只有同一操作两端结果一致，才记录该路径和操作的权限问题已解决；不能把云端 Linux 自测当成 Windows 权限验收。

已在获授权的真实 Windows 电脑通过实际连接核验：elevated=true、High 完整性、受限 SID 数为 0。临时目录和 Program Files 下的创建/读写/重命名/删除通过，服务管理器完整访问、服务查询/修改配置句柄及 HKLM SOFTWARE 可写句柄通过；受保护系统 DLL 的写句柄被系统拒绝。临时文件已清理，未修改服务、注册表或系统文件。没有采集本机 Codex 同一失败操作的完整对照，不能据此宣称历史所有 Access Denied 已解决。
