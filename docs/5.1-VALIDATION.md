# 5.1 本次修改与验证

本次仅实现已确认的启动权限、双向多连接和统一界面要求，以及第六台请求时的指定替换弹窗。旧后台识别、版本比对和更新功能已撤销，不包含在最终运行包中。

## 使用

- Windows 运行包：完整解压内层 `SSHRelayPro-5.1-win32-x64.zip`，运行 `Start.cmd`；`Restart.cmd` 用于重新打开界面，已有窗口会被聚焦，不中断正在执行的任务。
- 首次点击“首次授权并安装管理员后台”，确认系统 UAC。安装并立即启动两项 SYSTEM 服务。以后正常打开界面复用服务，不再次请求启动提权。
- “连接其他电脑”和“允许其他电脑连接本机”独立开启，可同时开启，保存各自状态。首次安装默认关闭，已有配置与配对保留。
- 两端设备列表都有逐台断开按钮。断开保留配对，其他连接保持。
- 远端已连接五台近端时，第六台请求弹窗提供“保留现有连接”和“替换 1–5”，并列出五台名称及身份后缀。选择后只暂停所选连接，腾出的名额暂留给该请求；取消不自动抢占。
- 开发模式：源码根目录运行 `Start-Dev.cmd` 或 `./Start-Dev.sh`，需要本机 Node/npm。Windows 开发入口准备固定校验版本的服务宿主，不自行提权。
- MCP 配置：运行包中的 `Generate-MCP.cmd` / `Generate-MCP.sh` 生成当前解压位置的 `MCP-CONFIG.json`。

Windows 服务使用 SYSTEM 账户，其默认目录和桌面账户不同。原普通账户后台首次切换为 SYSTEM 时，既有身份核验可能要求近端显式重新确认新账户；没有绕过原有账户变化校验。

## 修改边界

主要变更位于桌面界面、启动器、服务配置和打包脚本。运行时仅调整连接准入、单连接暂停/恢复、必要的服务复用和私有状态权限衔接。命令执行、SFTP、转发、持久任务及配对密码学实现未重构。设备记忆与自动重连沿用原有实现。

打包直接复制源码、固定校验的 Electron 和完整生产依赖，使用低压缩级别，避免额外编译和高压缩负载。数据库服务器、数据库客户端工具和 AI 客户端不是本运行包的内置组件。

## 实测

1. 15 项针对连接名额、显式替换、取消、身份签名、状态写入及启动配置的局部检查通过。
2. 源码与最终 Linux 运行包分别通过真实公共中继验证：五个独立近端身份同时向同一远端执行；第六个拒绝且不扰动现有五个；显式替换指定连接仅影响该连接；远端逐条暂停与恢复；一个近端同时向五个远端执行；第六个目标名额限制；近端断开单个目标后其他四个继续执行；原 SFTP 上传下载逐字节一致。验证使用同一宿主上的隔离 Agent 身份，不冒称五台物理电脑实测。
3. 原生 Windows Server 2022 验证：两项 SYSTEM 服务实际启动；客户端复用相同服务 PID；系统服务管理器核对 LocalSystem；两项功能独立开关；桌面重新加载恢复状态；SCM 重启后保存状态；真实桌面截图。此项不冒称 Windows 10 实机验收。
4. Windows 原生弹窗使用隔离界面数据，逐一实际点击“保留现有连接”和“替换 1–5”，六次均检查完整选项、正确目标 ID 与退出行为。实际中继指定替换另由第 2 项覆盖。
5. 最终开发窗口与最终打包窗口均实际启动。相同视口 1060×1400，排除实时钟表与日志区域后静态 UI 像素差为 0。没有提供外部设计参考图，不声称与外部设计稿像素一致。
6. 取回 Windows 验证产物并核验运行包 SHA-256；运行包源码与当前分支逐文件比较一致（忽略平台换行）。最终 Linux 包也与当前运行源码逐文件哈希一致。
