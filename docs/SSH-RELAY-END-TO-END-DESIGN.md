# SSH Relay 端到端整合方案

日期：2026-10-19  
状态：待实现的整合设计；本文不表示现有版本已完成改造。

## 1. 要达到的结果

原有功能全部保留。现在依赖连接 skill 才能串起来的流程，全部整合到两端软件。

用户打开远端软件，生成连接码；AI 调用一次连接接口，之后直接执行任务。AI 不读连接 skill，不管理后台、目录、指纹、连接报告，不负责诊断内部故障或组织重试。

远端运行本项目的软件及后台 Agent，不要求安装 Codex CLI，也不要求用户使用命令行。

## 2. 整合后的结构

```text
AI
 │ MCP；不支持 MCP 时使用同等功能的少量接口
 ▼
近端统一服务
 ├─ 配对、设备和授权管理
 ├─ 自动启动、连接验证、重连和故障处理
 ├─ 原有全部业务工具
 └─ 操作状态和结果查询
          │
          │ 端到端认证、加密和可靠传输
          │ 公共中继只负责转发
          ▼
远端统一服务
 ├─ 生成连接码、授权和身份验证
 ├─ 执行命令、会话、文件及原有业务能力
 ├─ 操作记录、结果保存和传输恢复
 └─ 后台守护、故障处理和状态反馈
```

两端界面、MCP 和自定义 CLI 都调用同一套服务，不各自实现连接逻辑。公共中继继续保留，不要求用户自建服务器。

## 3. AI 只接触这些入口

原有 37 个业务工具及其能力保留，包括命令、文件、会话、部署、备份、监控、数据库等。工具按实际授权和远端依赖返回可用性，不假装所有环境都有数据库或调度设施。

新增三个统一入口：

| 入口 | 用途 |
|---|---|
| connect(code 或 device_id) | 首次配对或连接已记住设备，返回可用设备 |
| devices() | 列出已授权设备、连接状态和能力 |
| operation_status(operation_id) | 查询长任务或中断任务的真实结果 |

每次业务调用指定 device_id，或使用显式绑定该设备的会话。现有业务工具内部统一走设备服务，不再要求连接报告路径、端口或角色目录。

业务调用正常时直接返回结果；耗时较长时返回 operation_id。内部恢复期间返回“处理中/恢复中”，由软件继续处理，AI 只查询结果。

撤销、断开等管理能力仍保留，可由远端界面或管理工具执行，不塞进每次任务流程。

## 4. 将 skill 中的流程落实到软件

| 现在交给 AI 的事 | 整合后由软件执行 |
|---|---|
| 选择 near/far 和状态目录 | 根据本端动作确定职责，统一管理私密状态 |
| 启动后台、避免重复实例 | 服务自动就绪、单实例协调、守护恢复 |
| 判断有没有配对、查设备 | 授权库查找并复用已有设备身份 |
| 保存配对码文件、调用配对命令 | connect 接收连接码，内部完成配对并清理临时数据 |
| 查找 connectionReport | 服务内部管理连接信息，不对 AI 暴露路径 |
| 核对指纹、主机、账户 | 两端自动认证并返回已验证身份 |
| 判断是否真的在线 | 实际业务探测，通过后才返回 ready |
| 分析日志、区分故障阶段 | 内置诊断和确定的恢复策略 |
| 三次重试、退避、重启 | 服务统一调度，避免叠加循环和重复进程 |
| 断线后判断任务是否执行 | 查询远端操作记录，返回结果或明确未知 |
| 配置 Windows/Linux 执行方式 | 远端适配器选择系统执行器和编码 |
| 找日志、脱敏、整理错误 | 输出结构化状态，诊断信息默认脱敏 |

不把这些步骤搬到另一份 skill、长 MCP 提示词或必读手册里。

## 5. 一次连接的完整流程

1. 远端软件启动接收服务，生成默认五分钟有效的一次性连接码。
2. 用户把码交给 AI，AI 调用 connect(code)。
3. 近端自动准备本地服务，找到远端并完成加密配对。
4. 两端各自保存密钥，绑定设备身份及本次授权；连接码失效。
5. 建立业务通道，验证真实主机、账户和权限。
6. 返回 device_id、设备名称、系统、实际账户、可用能力及 ready。
7. 以后 connect(device_id) 或业务调用复用原授权；普通断线不索要新码。

配对成功但业务通道暂时失败时，保存授权继续连接。配对确认丢失时恢复原次配对，不重复授权。

中继不能读取业务明文。设备身份异常时阻断连接，不通过关闭校验解决。

## 6. 一次业务操作的完整流程

1. 近端接收业务调用，绑定设备、授权和唯一请求 ID。
2. 自动检查连接；需要恢复时由服务恢复。
3. 远端检查权限，记录操作 ID 后执行；重复请求不再次启动同一操作。
4. 保存执行状态、退出码和输出，将真实结果返回近端。
5. 连接中断后，近端用操作 ID 查询原任务，不自动重发业务动作。
6. 长任务支持查询与取消；取消不等于回滚。

命令、上传、部署、数据库操作都遵循这一规则。无法确定是否完成时返回“结果未知”，软件继续尝试查询，不能编造成功或盲目重跑。

文件传输使用临时文件、分块确认和完整校验。断线后检查源文件和已收数据，再恢复传输；最终校验通过才提交目标文件。覆盖策略明确，避免重连造成误覆盖。

原会话仍存活时可以续用；进程已丢失则明确返回会话结束，不能把新会话冒充旧会话。

## 7. 内部故障由两端自行处理

| 故障 | 软件处理 |
|---|---|
| 本地后台没启动 | 按需启动并验证就绪 |
| 重复启动或并发请求 | 单实例复用、请求协调 |
| 网络抖动、中继暂时不可达 | 自动重连、退避、必要时使用受支持的备用中继 |
| 工作进程崩溃 | 守护拉起，复用原身份，重新验证通道 |
| 旧连接信息、失效端口 | 内部刷新，不要求 AI 手改文件 |
| 配对确认或执行结果丢失 | 用原握手或操作 ID 取回 |
| 文件传输中断 | 校验后续传，不让 AI 重写传输流程 |
| 多客户端同时连接 | 独立授权和通道，互不抢占 |
| 内部状态损坏 | 从可验证的一致状态或备份恢复，不猜测密钥和授权 |

处理必须有时间和次数边界，长恢复作为后台任务继续。对 AI 返回当前状态与最终结果，不倾倒内部堆栈让 AI 修服务。

以下情况不能靠软件强行“修复”：远端关机、授权被撤销、密钥丢失、设备身份变化、系统权限不足、缺少业务依赖。软件给出准确原因和最小必要动作，不能绕过权限或偷偷重新授权。

用户主动断开后停止对应自动重连；用户撤销授权后两端拒绝旧身份继续访问。

## 8. 现有代码如何整合

| 现有部分 | 改造方向 |
|---|---|
| src/pro/agent.cjs、guardian.cjs | 承担统一服务与恢复调度，收拢状态判断，消除多处重复恢复 |
| src/pro/pairing.cjs、keys.cjs、store.cjs | 统一配对、身份、授权和事务式状态保存 |
| src/pro/worker.cjs、near.cjs、remote.cjs、relay.cjs | 作为内部通道与远端执行组件，不再要求 AI 拼接启动 |
| src/mcp.cjs、src/mcp/config.js | 从读取外部报告启动，改为对接统一设备服务 |
| src/mcp/transport.js、handlers.js | 业务请求通过设备 ID 取连接，接入操作 ID、结果查询和恢复语义 |
| src/pro/cli.cjs | 成为统一服务的薄入口，提供机器可读结果，复用 MCP 同一核心 |
| desktop/ | 复用同一服务，负责生成码、设备展示和授权管理 |
| 连接 skill 与强制引用 | 新流程验证完成后移除，不再作为使用条件 |

这些是模块职责调整，不意味着替换全部现有实现。先盘点原有工具与行为，建立逐项能力对照，避免整合时丢功能。

## 9. 实施顺序

1. 统一近远端服务、设备 ID、授权和连接状态，封装自动验证与恢复。
2. 打通 connect：从连接码直接得到可用设备，不需要外部连接报告。
3. 原有全部工具接入统一服务，补操作记录、查询和文件恢复。
4. MCP 和少量接口共用核心；远端界面直接操作同一后台。
5. 完整流程验收通过后，移除连接 skill 依赖与旧入口说明。

本次仅更新设计文档，不提前删除旧 skill 或修改软件。

## 10. 验收只看实际闭环

- 不给 AI 任何连接 skill，只提供 MCP 工具说明或少量接口说明，能用连接码完成真实远端操作。
- 远端只打开项目软件，不安装 Codex CLI、不操作命令行。
- 原有全部功能逐项验证，未支持的平台或依赖明确报告。
- 两端断网、进程崩溃、连接信息失效后软件自行恢复，不要求 AI 管目录、报告、进程或重试。
- 命令中断能查询真实结果，不重复执行；无法确定时明确未知。
- 文件中断后正确恢复并校验，多客户端互不干扰。
- 身份替换、错码、重放和撤销不能绕过授权，中继无法读取业务明文。
- 在实际 Windows/Linux 目标和最终下载运行包上验证，不用本地工具发现代替远端验收。

完成标准：原来靠 skill 指挥 AI 串联的工作，成为两端软件内部可执行、可恢复、可验证的流程；AI 只表达操作意图并读取结果。
