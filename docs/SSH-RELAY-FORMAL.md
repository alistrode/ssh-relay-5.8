# SSH Relay 有界形式化检查

依据：本分支 `docs/SSH-RELAY-DEVELOPMENT-HANDOFF.md`，2026-10-20。

目标：一个近端最多管理五台独立设备，CLI/MCP 共用认证 Agent 状态，同时保留旧报告模式。本文仅检查其中的槽位准入及异步发现发布，不代表整个系统已获形式化证明。

## 状态、迁移和不变量

槽位模型：设备集合 D，注册状态 R(d) ∈ {不存在, 停用, 启用}，固定排序 ≺ 表示配对时间及设备 ID 的顺序。E 是启用设备集合；A 是 E 中按 ≺ 排序的前五个；P = E \ A。迁移包括启用/重复配对、停用、取消配对、重启观察；迁移中不加入网络连通性，离线不释放槽位。

- S1：|A| ≤ 5，A ∩ P = ∅，A ∪ P = E。
- S2：准入成功当且仅当 d ∈ A 或 |E \ {d}| < 5；拒绝不改变 R。
- S3：重复启用 d ∈ A 保持 A/P 不变（保留配对排序）；停用或取消配对后 d ∉ A。
- S4：快照及重启观察不修改注册数据，旧溢出数据保留且落入 P。

归纳论证：初始 A 按定义最多五个。成功准入到原非启用集合时，其余启用设备少于五个；重复准入不增加设备。停用/删除只减少 E；历史溢出始终经前五项截断。因此这些抽象迁移保持 S1。排序保持不变时重复迁移保持 S3。该论证不涉及真实 worker 尚未退出时的瞬时进程数。

发现模型：G 是最近开始的刷新代次，C 是已发布快照，ticket 是每个请求持有的代次。Start：G := G+1，C := 空。Success(ticket, payload)：仅 ticket = G 时发布 payload，否则拒绝该刷新。Failure：不发布。API 的认证与在线设备过滤另由已有实现/局部检查覆盖。

- D1：C 非空 ⇒ 发布 C 的 ticket = G。
- D2：最新请求启动到成功发布之间 C 为空；最新请求失败不会回退到旧快照。
- D3：旧请求完成，无论成功还是失败，都不能覆盖较新的快照。

归纳论证：Start 清空 C，维持 D1；只有 ticket = G 的 Success 可令 C 非空；Failure 和过期响应不写 C。因此任意有限事件序列保持 D1–D3。这里的「最新」指请求启动顺序，不是远端状态与业务执行瞬间的原子一致性。

## 反例及修复

原 `refreshAgentServers` 在 await 后无条件赋值，存在反例：Start(A) → Start(B) → B 返回停用后的列表 → A 返回停用前的旧列表。最终旧列表覆盖新列表，违反 D1/D3。

已在 `src/mcp/agent-provider.js` 增加 `createAgentDiscovery`，用递增代次保护发布；`config.js` 使用该实现。旧请求被明确拒绝，可由调用方重新发起读取，不重放业务操作。

## 可复现结果

执行：`node scripts/formal-relay.mjs`。脚本直接调用生产 `DeviceSlots` 和 `createAgentDiscovery`，没有重新写一份待验证算法。它另保留无保护的旧算法作为反例检查，确认模型能发现原缺陷。

2026-10-20 北京时间 23:30:14 的结果：

- 七个设备的全部 3^7 = 2187 个注册状态，45927 个迁移检查通过；包含所有旧数据溢出状态。固定配对排序；设备标识按该排序对称抽象，不穷举时间戳本身。
- 三个异步请求的全部 15 种合法事件交错 × 8 种失败组合 × 8 种响应内容组合，共 960 个场景通过。
- 旧实现的上述反例被成功检出。

## 证明边界与后续

本结果是生产函数上的有界显式状态检查，加上抽象迁移的不变量归纳说明；没有经过独立证明助手审查，不是整个 JavaScript 应用的无界精化证明。

尚未建模：Agent 配对回调和 worker/SSH 生命周期、停止进程与重连的时间窗口、注册文件与报告文件的并发读取、真实五主机互不干扰、平台行为、已建立会话的撤销边界及业务副作用。不得据此声称这些性质已证明。

无限刷新可能不断使旧请求过期；网络一直失败或调度不公平时不保证最终连接成功。本轮证明的是上述安全不变量，尚未证明系统活性。

每五分钟上传节点不执行本脚本或其他验证；源码保存与验证结果分开记录。
